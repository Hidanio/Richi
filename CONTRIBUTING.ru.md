# Участие в разработке Richi

[English](CONTRIBUTING.md) | Русский

Идеи, сообщения об ошибках и замечания к документации приветствуются. Richi использует
[Richi Personal Use and Organization Agreement License](LICENSE.md); организационное
и коммерческое использование требуют отдельного разрешения.

<a id="reports-and-proposals"></a>
## Сообщения и предложения

Если доступен трекер задач, опишите проблему, ожидаемое поведение, шаги
воспроизведения и соответствующую версию. Иначе свяжитесь с автором:
[hidanjkezor@gmail.com](mailto:hidanjkezor@gmail.com).

Используйте минимальные синтетические примеры. Не включайте учётные данные,
частные базы знаний, закрытый код проектов, персональные данные и конфиденциальные
логи. Чтение публичного кода и отправка описания или предложения сами по себе
не требуют отдельного соглашения. Запуск или изменение Richi для организации
по-прежнему регулируются лицензией, в том числе при исследовании ошибки.

<a id="code-and-documentation-patches"></a>
## Изменения кода и документации

Прежде чем готовить изменение кода или документации для включения в проект,
свяжитесь с Richardas Kuchinskas:
[hidanjkezor@gmail.com](mailto:hidanjkezor@gmail.com). Сначала согласуйте объём
работы и применимые условия участия. Изменения третьих лиц принимаются для
включения только после письменного оформления необходимых прав.

Вы сохраняете права на свою оригинальную работу. Pull request не считается
автоматической передачей авторских прав или общим разрешением сопровождающему
коммерчески лицензировать вашу работу на иных условиях. Для распространения
вклада как по лицензии проекта, так и по отдельным организационным или
коммерческим соглашениям требуется соответствующее разрешение.

Предоставляйте только материалы, на которые у вас есть необходимые права.
Работа, созданная для работодателя или заказчика, может требовать его разрешения.
Указывайте сторонние материалы и их лицензии; не представляйте их как
оригинальный код Richi.

Эта политика не отменяет права, независимо предоставленные применимым законом,
условиями платформы размещения, существующими лицензиями или применимым
отдельным соглашением.

<a id="development"></a>
## Разработка

В именах веток не используйте префикс `codex/`; вместо дефисов используйте
подчёркивания, например `audit_fixes_bilingual_docs`.

Используйте macOS или Linux, Python 3.9+ и Git. Установите текущий checkout
обычным способом во временное виртуальное окружение. Из корня репозитория:

```sh
richi_test_venv="$(mktemp -d "${TMPDIR:-/tmp}/richi-tests.XXXXXX")"
python3 -m venv "$richi_test_venv"
. "$richi_test_venv/bin/activate"
python -m pip install --upgrade pip
python -m pip install .
python -m unittest discover -s tests -v
python evals/evaluate_recall.py
```

После изменения исходников выполните `python -m pip install --force-reinstall .`
перед повторным запуском полного набора тестов и оценки. Прямые импорты Python
и smoke-тесты пакета используют установленный пакет; проверка старой установки
может пропустить регрессии в checkout. Editable-установки не поддерживаются:
запускателю нужен фиксированный пакет для release-режима и восстановления.

Для повседневной разработки CLI настройте `development.source` и `dev true`,
как описано в [руководстве установки](docs/INSTALLATION.ru.md). Это выбирает
`src/richi/` для CLI, агентов и карты. Настройка не перенаправляет прямые импорты
Python и не загружает изменения запускателя из checkout; изменения в `launcher/`
требуют переустановки пакета.

Тестовые данные должны быть синтетическими. Тесты создают временные базы и
репозитории; не направляйте набор тестов на живое хранилище знаний. Конфигурация
runtime и данные находятся вне пакета. Работа с CLI и совместимостью описана
в руководствах [установки](docs/INSTALLATION.ru.md) и [миграции](docs/MIGRATION.ru.md).

Полный skill агента находится в `skills/project-memory/`. Его каталог
`references/` — канонический источник подробной документации команд.
Индекс `docs/CLI.md` ссылается на него; сохраняйте контракты команд в одном месте,
чтобы для установки по-прежнему было достаточно скопировать всю папку skill.

При изменении поиска сохраняйте воспроизводимый пример и сравнивайте
соответствующие случаи до и после. [Руководство оценки](skills/project-memory/references/EVALUATION.ru.md)
различает синтетические регрессионные проверки и частные оценки по задачам.
Не публикуйте частные снимки и не переписывайте старые ожидания ради роста оценки.

Поддерживайте английские документы `*.md` и их полные русские переводы
`*.ru.md` синхронно. Сохраняйте переключение языка и перекрёстные ссылки;
локальные ссылки на документацию должны вести на соответствующий язык.
Не переводите команды и идентификаторы API. `LICENSE.md` остаётся исходным
текстом лицензии.
