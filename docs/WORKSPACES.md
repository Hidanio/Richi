# Рабочие области

Workspace объединяет несколько связанных проектов и их знания. У каждой области
своя SQLite-база, история записей, определения, связи, Git-снимки, настройки и
логи карты. Один репозиторий можно добавить в несколько workspace: проекты и
знания регистрируются независимо в каждой базе, совпадающие ID не пересекаются.
Поиск и граф работают только с выбранной областью.

## Создание и переключение

```sh
richi workspace list
richi workspace current
richi workspace create work
richi -w work init
richi -w work project add /path/to/service-api
richi -w work project add /path/to/service-storage --id storage
richi use work
richi project list
richi map
```

`workspace create` создаёт настройки пустой области; `init` явно создаёт её базу.
Команды не копируют знания из текущей области и не клонируют репозитории.
`project add` принимает существующую папку и сохраняет её абсолютный путь.
По умолчанию ID и имя проекта берутся из имени папки; доступны `--id`, `--name`
и `--description`. Повторное добавление того же ID и пути сохраняет ранее
записанные метаданные. При конфликте ID с другим путём команда выдаёт ошибку.
Для осознанного редактирования метаданных остаётся `project upsert --json FILE`.

```sh
richi use personal
richi use default
# В терминале без имени — пронумерованный список для быстрого выбора:
richi use
```

Переключение меняет область по умолчанию для последующих команд. Оно не
останавливает уже запущенные операции и карты. В неинтерактивной среде имя
обязательно: Richi не пытается читать меню из входного JSON агента.

`default` использует существующую конфигурацию и память: установка поддержки
workspace не переносит и не разделяет старые записи. Для новых областей Richi
выделяет отдельные каталоги `workspaces/NAME/` внутри платформенного каталога
данных. Реестр `workspaces.json` хранится в платформенном каталоге конфигурации.
Фактические пути показывает `richi -w NAME config show`.

## Несколько чатов и агентов

Для каждой задачи закрепляйте workspace явно во **всех** вызовах:

```sh
richi -w work recall 'решение по кешу' --project service-api
richi -w work entry get task:DEMO-17
richi -w personal project list
```

Или задайте `RICHI_WORKSPACE=work` в окружении отдельного терминала/процесса
агента. Глобальный `richi use` удобен человеку, но агент не должен менять его
для своих задач: другой чат может работать с другой областью.
`--project` выбирает проект внутри текущей базы; он не переключает workspace.

Порядок выбора: явный `--workspace/-w` либо `--config` (вместе запрещены), затем
`RICHI_CONFIG`, затем `RICHI_WORKSPACE`, затем выбранная по умолчанию область.
Явный workspace имеет приоритет над `RICHI_CONFIG`. Неизвестное имя приводит
к ошибке, без возврата к другой базе.

Именованные workspace используют закреплённое размещение базы и Git-снимков.
Для них `--db`, `RICHI_DB` и `RICHI_DATA_DIR` запрещены, чтобы старое окружение
не направило запись в чужую область. Уберите эти переопределения перед работой
с workspace. Для специальных операций с отдельно выбранной базой можно
использовать явный `--config`; это отдельный способ выбора хранилища.

## Код, режим разработки и карта

Изоляция касается памяти Richi. Если в двух workspace указан один путь
репозитория, файлы и рабочая копия Git общие: изменение кода видно обоим.
Для независимых изменений подключайте разные Git-worktree или checkout.
Richi не создаёт их автоматически и не предоставляет разграничение доступа
между пользователями операционной системы.

Новая область наследует текущие `dev` и `development.source` при создании.
Далее её настройки независимы:

```sh
richi -w work config set development.source /path/to/Richi
richi -w work config set dev true
richi -w personal config set dev false
```

Dev и обычная версия внутри одного workspace используют одну базу. Переключение
режима не переносит знания между областями и не применяет миграции SQLite.
Изменения установленного launcher требуют переустановки пакета.

`richi -w work map` открывает карту этой области. Карта показывает имя workspace
и остаётся привязана к своей базе, даже если позднее вызвать `richi use personal`.
Для другой области запускается отдельная карта на свободном локальном порту.
Настройка dev и перезагрузка исходников также остаются привязаны к исходной
области. Переключение default не меняет содержание уже открытой вкладки.
