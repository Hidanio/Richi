# Как попробовать Richi с коллегами

[English](TESTING.md) | Русский

Инструкция предназначена для локального Codex на macOS или Linux и исправленного
стабильного релиза **1.0.1**. Начинайте после успешного завершения
[workflow релиза](https://github.com/Hidanio/Richi/actions/workflows/release.yml),
когда на [странице релиза](https://github.com/Hidanio/Richi/releases/tag/v1.0.1)
появятся wheel, `richi-release.json`, `richi-installer.pyz`, его файл SHA256
и `install.sh`. Прежний пустой релиз `v1.0.0` не позволяет установить или обновить Richi.

## Установка и подключение Codex

Нужны Python 3.9+ с `sqlite3`, `venv` и `ensurepip`, а также `curl` и доступ к сети.
В Debian/Ubuntu для отсутствующего `venv` может потребоваться `python3-venv`.
В обычном терминале скачайте официальный скрипт установки и запустите его:

```sh
(
  set -eu
  richi_install_script=$(mktemp)
  trap 'rm -f "$richi_install_script"' EXIT HUP INT TERM
  curl --fail --silent --show-error --location --proto '=https' --proto-redir '=https' \
    https://github.com/Hidanio/Richi/releases/latest/download/install.sh \
    -o "$richi_install_script"
  sh "$richi_install_script" --yes
)
```

Устанавливается последний стабильный релиз в отдельное окружение; настраиваются
команда, skill Project Memory и глобальные инструкции Codex для пользователя ОС.
Старые разговоры не импортируются, база workspace не создаётся. При конфликте
существующей команды или пользовательского skill остановитесь и следуйте
[инструкции setup](SETUP.ru.md); не перезаписывайте старую установку и не
добавляйте `--replace-skill` без разбора конфликта.

Откройте **новый терминал и новый чат Codex**. В терминале проверьте:

```sh
command -v richi
richi --version
richi setup --status
richi update check
```

Ожидаются `Richi 1.0.1` (или более поздняя стабильная версия), статус setup
`configured` и проверка обновлений без ошибок. Если PATH не обновился,
используйте `~/.local/bin/richi`. Для существующей управляемой установки выполните
`richi update check`, затем `richi update apply`; режим dev в workspace может
по-прежнему выбирать локальные исходники. См. [обновления](UPDATES.ru.md).
Старому bootstrap без поддержки setup требуется отдельное окружение по
[инструкции setup](SETUP.ru.md). Не перезаписывайте управляемую установку через pip.

## Проверка памяти между двумя чатами

Откройте новый чат Codex без проекта и отправьте:

> Для этого чата используй только workspace `richi_test`. Создай его при
> необходимости, привяжи к нему чат и при необходимости инициализируй пустое
> хранилище. В этом workspace используй установленный релиз (`dev false`).
> Другие workspace не читай. Создай синтетический проект `test_demo` без пути
> к репозиторию. Сохрани подтверждённую заметку `note:orion-test` с заголовком
> «Orion test»: «Синтетический тест: Orion использует тайм-аут 30 секунд.
> Это не production». Привяжи её к `test_demo` и укажи источник как вручную
> предоставленные синтетические тестовые данные. Покажи workspace и ID записи.

Если в `richi_test` уже есть другая работа, выберите новое тестовое имя и
используйте его везде одинаково. В каждом новом чате нужен явный выбор workspace.
Затем в обычном терминале:

```sh
richi -w richi_test check
richi -w richi_test entry get note:orion-test
richi -w richi_test recall Orion --project test_demo
richi -w richi_test map
```

Ожидаются исправная база и заметка в recall и на карте. Во **втором новом чате**
явно выберите `richi_test` и попросите агента найти и прочитать заметку Orion,
назвать тайм-аут и сказать, относится ли она к production, без изменения памяти.
Ожидаются 30 секунд и явное указание на синтетические данные. Так проверяется
сохранение между чатами; Richi не импортирует историю разговоров.

## Обратная связь

Приложите ОС, версию Python, `richi --version`, статус setup, шаг с ошибкой,
ожидаемое и фактическое поведение, минимальное синтетическое воспроизведение.
Укажите, смог ли второй чат использовать сохранённую заметку. Удалите приватные
пути и содержимое; не отправляйте базы, резервные копии setup и личные логи.
