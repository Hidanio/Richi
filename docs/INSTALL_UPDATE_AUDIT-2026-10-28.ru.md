## Путь релиза

1. `update check` получает `releases/latest` либо точный `tags/vX.Y.Z` из
   `Hidanio/Richi`. Draft/prerelease отвергаются.
2. Проверяются manifest, версия/tag, ожидаемые адреса и имена assets, протокол,
   Python и контракт схем. Базы workspace не открываются.
3. `apply` проверяет размер, SHA256, metadata и структуру wheel, затем создаёт
   отдельный venv кандидата. Установка использует `--no-index --no-deps`.
4. После self-check, проверки разрешения и блокировок переключается runtime.
   Managed skill согласуется с ним через recoverable setup journal.
5. Сохраняются current и previous; leases удерживают используемые процессами
   версии. `rollback` работает без сети, cleanup допускает повтор.

| Ответ check | Значение |
| --- | --- |
| `no_release` | Стабильного релиза нет. |
| `update_available` | Более новая подходящая версия. |
| `release_available` | Номер совпадает с checkout-сборкой без подтверждённого SHA; допустим первый переход на release. |
| `up_to_date` | Версия и подтверждённый SHA совпадают. |
| `older_release` | Downgrade через apply запрещён; доступен явный rollback. |
| `incompatible_release` | Не подходит Python или контракт схем; `can_apply: false`. Неизвестный протокол отклоняется при чтении manifest. |
| `release_changed` | Уже установленный проверенный номер опубликован с другим SHA; требуется новый номер версии. |

`auto enable --interval 6h` включает проверки. Автоустановка требует отдельного
`--install`. Системное задание просыпается каждые 15 минут; Python проверяет
due time, backoff, политику и блокировки. Повторный enable без `--install`
отзывает разрешение установки; ручной rollback приостанавливает автоустановку.
Системных уведомлений пока нет, результат читается через `auto status`.

В проверенной постоянной установке `enabled=false`, `auto_install=false`,
задание ОС не зарегистрировано. При аудите оно не включалось.

## Публичная установка

После включения исправлений в релиз нужно согласовать version/tag и запустить
release workflow. Он проверяет точные artifacts в матрице перед публикацией
wheel, manifest, installer `.pyz`, checksum и `install.sh`. До публикации
one-command URL недоступен, а корректный ответ updater — `no_release`.

Старая bootstrap-установка без setup-протокола требует отдельного перехода по
[SETUP.md](SETUP.ru.md), а не `pip install -U` поверх managed generations.
Постоянная установка и личная интеграция агента этим аудитом не заменялись.
