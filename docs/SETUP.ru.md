<a id="one-command-installation"></a>
# Установка одной командой

[English](SETUP.md) | Русский

В примере установщик подключает Codex. Для Claude Code замените `codex`
на `claude`.

```sh
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/Hidanio/Richi/releases/latest/download/install.sh | sh -s -- --agent codex --yes
```

Для локального Cursor Agent нужен Richi 1.2.0 или новее, для Antigravity —
1.2.2 или новее. Чтобы проверить текущий стабильный установщик, замените
`--agent codex --yes` в команде выше на `--help`. Если в списке агентов есть
`cursor` или `antigravity`, выполните команду с `--agent cursor --yes` или
`--agent antigravity --yes`. Если нужного агента пока нет,
[установите Richi из исходников](INSTALLATION.ru.md).

Нужны macOS или Linux, curl и Python 3.9+ с sqlite3, venv и ensurepip.
В Debian/Ubuntu может понадобиться пакет `python3-venv`. Для истории репозиториев нужен Git.

Установщик размещает фиксированный релиз в `~/.local/share/richi/venv`,
создаёт команду `~/.local/bin/richi` и подключает скилл Richi к указанному
агенту. Без `--agent` он выбирает Codex. Без `--yes` он показывает план и ждёт
подтверждения в терминале.

Откройте новый чат выбранного агента и выберите workspace. Агент может
инициализировать пустую базу после выбора. Откройте новый терминал для доступа
к команде через PATH или сразу используйте `~/.local/bin/richi`.
Для установки база workspace не требуется. Установщик сохраняет существующие
данные, настройки workspace и привязки чатов.

<a id="scope-and-existing-settings"></a>
## Область действия и существующие настройки

В Codex установщик создаёт ссылку `~/.agents/skills/richi`.
Подключение действует для локальных чатов этого профиля, включая чаты без проекта.
Установщик использует `${CODEX_HOME:-$HOME/.codex}/AGENTS.md`,
если приоритет не имеет непустой `AGENTS.override.md`. Другие профили, удалённые
хосты, облачные агенты и другие агентные продукты требуют отдельной настройки.
Открытые чаты могут сохранять прежние инструкции.

Блок инструкций разрешает использовать память в рамках задачи и сохранять
полезные результаты содержательной работы. Явные запросы только на чтение и
изоляция workspace продолжают действовать. Инструкции проекта или пользователя
могут сужать поведение. Setup никогда не редактирует `config.toml`, не ослабляет
настройки согласований и не обходит отключённые skills. Успех подтверждает
установленные файлы, а не выполнение агентом каждой инструкции. Setup отклоняет
инструкции, превышающие стандартный бюджет обнаружения Codex в 32 КиБ;
меньшие пользовательские бюджеты и отключённые skills нужно согласовать в
настройках Codex. См. официальные руководства по
[skills](https://learn.chatgpt.com/docs/build-skills) и
[обнаружению инструкций](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Codex может отключить отдельный скилл по пути к `SKILL.md` в записи
`[[skills.config]]` файла `$CODEX_HOME/config.toml`. При обновлении с v1.2.0 и
более ранних версий сначала проверьте путь в этой записи. Если он указывает
внутрь пакета, добавьте `enabled = false` для абсолютного пути к
`~/.agents/skills/project-memory/SKILL.md`, подставив домашний каталог вместо
`~`. При первом обновлении старый установщик сменит пакет, на который ведёт ссылка.
Лаунчер с поддержкой переименования проверяет настройки до изменения ссылок.
Если setup, обновление или переключение dev включило бы отключённый скилл,
команда останавливается. Чтобы сохранить отключение, оставьте прежнюю запись,
добавьте запись с `enabled = false` для нового пути к `SKILL.md` из сообщения
и повторите команду. Обе записи действуют и при откате. На Python 3.9–3.10
Richi использует TOML-парсер из pip, если он доступен. При отсутствии парсера
возможный запрет в конфигурации откладывает изменение до проверки в установке
Richi с поддержкой TOML.

Настройка PATH поддерживает zsh (`$ZDOTDIR/.zshrc` или `~/.zshrc`), bash
(`~/.bashrc` и первый существующий профиль входа; по умолчанию `~/.bash_profile`
на macOS или `~/.profile` на Linux), а также sh/dash (`~/.profile`).
Существующие байты сохраняются. Для другой оболочки или уже настроенного PATH
используйте `--no-path` и добавьте `~/.local/bin` самостоятельно. Desktop-агенты
могут использовать стабильную абсолютную команду из блока инструкций.

<a id="inspect-repeat-and-adopt-existing-skills"></a>
## Проверка, повторный запуск и принятие существующих skills

Для предварительной проверки скачайте установщик и посмотрите список поддерживаемых
агентов. В этом примере выбран Codex.

```sh
curl -fL --proto '=https' --proto-redir '=https' https://github.com/Hidanio/Richi/releases/latest/download/install.sh -o richi-install.sh
less richi-install.sh
sh richi-install.sh --help
sh richi-install.sh --agent codex --dry-run
sh richi-install.sh --agent codex --yes
```

Начальный скрипт скачивает самостоятельный установщик по HTTPS и проверяет его
SHA256 перед выполнением. Установщик проверяет контрольную сумму, размер,
идентичность и совместимость официального wheel. Контрольные суммы обнаруживают
повреждение; подлинность опирается на официальный GitHub-репозиторий и HTTPS.
Пакет с именем Richi из PyPI не загружается. Первая онлайн-установка обновляет pip
в выделенном окружении.

Повторный запуск использует принадлежащее установщику окружение, проверяет наличие
более нового стабильного релиза и согласует настройку без дублирования блоков
инструкций. Незавершённые первоначальные окружения сохраняются в резервные копии
`.interrupted-*` перед новой попыткой создания. В плане установщика `--dry-run`
поле `skills_directory` указывает родительский каталог скиллов агента. Имя
подкаталога выбирает устанавливаемый релиз с учётом доступной версии для отката.
Установленная команда показывает точный путь и проверяет конфликты интеграции.
Примеры ниже относятся к Codex. Для другого
клиента передавайте тот же `--agent`, что и при первоначальной установке.

```sh
richi setup --dry-run
richi setup --yes
richi setup --status
```

Существующие пользовательские skills требуют явного принятия под управление:

```sh
sh richi-install.sh --agent codex --yes --replace-skill
# Or, with a supported existing installation:
richi setup --yes --replace-skill
```

В Codex существующие каталоги и ссылки перемещаются в `~/.agents/richi-skill-backups/`,
за пределы обнаружения skills. Цели символических ссылок не меняются.
Прежние копии `${CODEX_HOME}/skills/project-memory` сохраняются в
`${CODEX_HOME}/richi-skill-backups/`, чтобы избежать дублирования skills.
Посторонние файлы команд, инструкции или родительские каталоги в виде symlink,
а также изменённые управляемые блоки приводят к понятной ошибке без перезаписи.
Правки вне управляемых блоков сохраняются.

Окружение без маркера владения установщика никогда не перезаписывается.
Используйте его `richi setup`, если он поддерживается. Если постоянный bootstrap
создан до появления setup, нужен новый пустой `--prefix`: сохраните старое
окружение и согласуйте его ссылку команды перед подключением замены. Данные
workspace независимы от окружений. Никогда не запускайте `pip install -U`
в управляемой установке с подготовленными релизами.

<a id="updates-rollback-and-development"></a>
## Обновления, откат и разработка

```sh
richi update check
richi update apply
```

Чтобы позже вернуть предыдущий релиз, выполните `richi update rollback`.

При новой установке Richi 1.2.1 и новее скилл регистрируется под именем `richi`. Обновление
доставляет переименованный скилл всем подключённым агентам. Пока для отката
нужен релиз, который ожидает `project-memory`, управляемый каталог и блок
инструкций сохраняют прежние имена. В новых чатах Codex скилл уже отображается
как Richi. Когда оба релиза поддерживают переименование, обновление переносит
управляемую ссылку и обновляет блок инструкций.
Если в рабочем dev-checkout есть только `project-memory`, агенты продолжают
использовать этот checkout и прежнее имя скилла.

Если после обновления со старой версии агент видит ваш собственный скилл
`richi`, ближайший вызов `richi chat current` покажет пути в `skill_conflicts`.
Проверяются и скиллы в папках с другим именем, у которых указано `name: richi`,
и скиллы, которые Cursor находит в профилях других агентов. Поле `managed_skill`
указывает на проверенную копию Richi. Свой скилл можно переименовать или
перенести за пределы каталогов поиска. Для путей, которыми управляет установщик,
команда также предложит посмотреть план резервного копирования.

В переходный период клиенты, которые формируют команду по имени каталога, могут
сохранить прежнюю команду. В Cursor имя каталога должно совпадать с именем
скилла, поэтому команда `/richi` может появиться только после переноса каталога.
До этого хук сессии передаёт агенту путь к установленному `SKILL.md`.
[Формат скиллов в Cursor](https://cursor.com/docs/skills#frontmatter-fields).

Во вложенных каталогах навыков Richi проверяет до 100 000 записей на корневой
каталог. При достижении лимита установка и переименование останавливаются до
изменения профиля. В переходный период `chat current` перечисляет частично
проверенные каталоги в `skill_conflicts[].incomplete_roots`. Перенесите
посторонние файлы за пределы этих каталогов и повторите команду.

Полный skill и справочники включаются в wheel из `skills/richi/`.
Обновление и откат переводят его управляемую ссылку на соответствующий пакет.
Восстанавливаемый файловый журнал согласует ссылку skill, метаданные владения
и указатель runtime. Прерванная активация завершается или отменяется при
следующем вызове CLI, кроме справки, `richi --version` и только читающих
`richi setup --status`, `richi setup --dry-run` и `richi agents --status`.
Изменённые файлы skill или заменённые ссылки блокируют
активацию и сохраняются. Релизы без протокола setup не могут заменить управляемую
интеграцию. После обновления откройте новый чат: работающие агенты могут сохранять
уже загруженное содержимое skill.

Автоустановка остаётся выключенной до явного включения через
`richi update auto enable --interval 6h --install`; см. [UPDATES.md](UPDATES.ru.md).
Dev-настройки workspace сохраняются. Для каждого подключённого агента
`richi config set dev true` направляет ссылку на навык в `skills/richi` внутри
checkout или в `skills/project-memory`, если прежнее имя нужно для отката или
закреплённой версии checkout. Команда `richi config set dev false` возвращает
ссылку на навык из релиза. При смене имени каталога запускатель обновляет имя
навыка в управляемых инструкциях в той же восстанавливаемой транзакции.
Результат виден в `agent_skills`. Запускатель, хуки и блоки PATH берутся из установленного релиза.
Ссылки общие для пользователя и следуют последней команде `config set dev`
в любом зарегистрированном workspace; разовые файлы `--config` или
`RICHI_CONFIG` их не переводят. Обновления и откаты сохраняют ссылки на checkout; перед откатом
на 1.1.0 или более старый релиз выполните `richi config set dev false`.
Подробности: [что переключает dev](INSTALLATION.ru.md#что-переключает-dev).

`richi setup --status` показывает `skill_mode` (`release` или `dev`) и ожидаемую
`skill_link`. Dev-ссылка, у checkout которой пропал skill, получает статус
`repair_required` с `dev_skill_error`; `richi setup --yes` тогда возвращает skill
релиза. Агент, подключённый позже, следует ссылкам уже подключённых агентов. Существующая
ссылка, уже указывающая точно на управляемую цель, принимается без
`--replace-skill`; для других существующих skills он по-прежнему нужен. Setup
никогда не редактирует исходный checkout.

<a id="offline-installation"></a>
## Офлайн-установка

Скачайте `richi-installer.pyz`, его контрольную сумму, `richi-release.json` и wheel
из одного доверенного релиза. Проверьте контрольную сумму архива. Пример ниже
подключает Codex. Для другого агента укажите параметр из справки `python3 -I richi-installer.pyz --help`.

```sh
python3 -I richi-installer.pyz --yes --wheel richi-X.Y.Z-py3-none-any.whl --manifest richi-release.json
```

Офлайн-режим использует ensurepip без онлайн-обновления pip. Повторная установка
того же первоначального wheel идемпотентна; для другого wheel нужен новый prefix
или проверенный путь `richi update apply --version X.Y.Z`. Параметр `--version`
онлайн-установщика закрепляет версию wheel, а не загрузку bootstrap. Перед
публикацией release workflow проверяет точные wheel и установщик на Python
3.9, 3.12, 3.13 и 3.14 в macOS и Linux; см. [RELEASING.md](RELEASING.ru.md).

<a id="backups-recovery-and-removal"></a>
## Резервные копии, восстановление и удаление

`richi setup --status` работает только на чтение и показывает управляемые пути
и ожидающее восстановление. Вывод setup содержит приватный каталог
`setup-backups`. Его JSON-файлы сохраняют исходные байты (base64), права доступа,
ссылки и пути резервных копий принятого skill. Они могут содержать приватные
инструкции: не публикуйте их. Сохраняйте ожидающий обработки `setup-pending.json`
и поколения установки для восстановления. Если после сбоя файлы менялись,
сохраните обе версии и согласуйте указанный путь перед повторной попыткой;
автоматическое восстановление откажется перезаписывать такие изменения.

Перед ручным удалением этой установки Richi выключите автоматические обновления.
В Antigravity удалите отдельный файл правила
`~/.gemini/config/rules/richi-project-memory.md`. В Cursor
удалите запись Richi из `sessionStart` в `~/.cursor/hooks.json` и отдельные файлы
`~/.cursor/richi/session_start.py` и `~/.cursor/rules/richi-project-memory.mdc`.
В файле глобальных инструкций Codex или Claude Code удалите только блок
`richi:project-memory`. Для Claude Code также удалите запись Richi из
`SessionStart` в `settings.json` и управляемый скрипт сессии.
Удалите блоки `richi:path` из указанных профилей оболочки. Проверьте цели перед
удалением управляемых ссылок skill и команды; при необходимости восстановите
указанную резервную копию skill. Затем удалите выделенное окружение и метаданные
его установки, если они больше не используются. Сохраните данные workspace.
В этом релизе нет автоматического деинсталлятора; для удаления интеграции никогда
не требуется удалять весь AGENTS.md.

## Подключение Codex, Claude Code, Cursor и Antigravity

Если Richi уже установлен, начните с `richi agents --status` в терминале.
Команда только показывает, каких клиентов поддерживает этот пакет, какие из них
обнаружены и для каких выполнена настройка. `richi agents` открывает меню
подключения. Чтобы подключить несколько клиентов, выполните настройку для каждого.

В Richi 1.0.1 подключайте Codex через `richi setup --yes` и проверяйте его
состояние через `richi setup --status`. Этот launcher выпущен до появления
меню агентов и параметра `--agent`. Для Claude Code нужен Richi 1.1.0 или новее,
для локального Cursor Agent — 1.2.0 или новее, для Antigravity — 1.2.2 или
новее. Когда выйдет стабильный релиз
с поддержкой нужного клиента, обновите старую установку командой `richi update apply`.
Перед подключением проверьте, что клиент есть в списке `richi setup --help`.
Список определяет установленный launcher, в том числе при включённом dev.

### Antigravity

На macOS Richi также находит Antigravity в `/Applications` и `~/Applications`
ещё до первого запуска, даже если команда клиента отсутствует в PATH.

```sh
richi setup --agent antigravity --dry-run
richi setup --agent antigravity --yes
richi setup --agent antigravity --status
```

Setup создаёт ссылку `~/.gemini/config/skills/richi` и устанавливает отдельное
глобальное правило `~/.gemini/config/rules/richi-project-memory.md`
(`trigger: always_on`), не затрагивая `~/.gemini/config/AGENTS.md` и `GEMINI.md`.
Существующий пользовательский skill при передаче `--replace-skill` сохраняется в
`~/.gemini/config/richi-skill-backups/`.

Откройте новый чат Antigravity. Antigravity передаёт в оболочку
`ANTIGRAVITY_CONVERSATION_ID` и `ANTIGRAVITY_AGENT=1`, и Richi определяет чат
как `antigravity:<id>`. Выберите workspace один раз для каждого чата.
Делегированные субагенты получают собственный ID, поэтому для работы с памятью
родительский агент передаёт им `--chat antigravity:<id>`. Если песочница
терминала Antigravity закрывает чтение вне рабочей папки — например,
пользовательских каталогов Richi или основного `.git` связанного worktree, —
разрешите доступ в настройках Antigravity или одобрите запуск `richi` вне
песочницы.

### Локальный Cursor Agent

На macOS Richi также находит Cursor в `/Applications` и `~/Applications`
ещё до первого запуска, даже если команда редактора отсутствует в PATH.

```sh
richi setup --agent cursor --dry-run
richi setup --agent cursor --yes
richi setup --agent cursor --status
```

Setup создаёт ссылку `~/.cursor/skills/richi`, устанавливает пользовательское
правило `~/.cursor/rules/richi-project-memory.mdc` и добавляет хук `sessionStart`
в `~/.cursor/hooks.json`, сохраняя другие хуки. Хук запускает скрипт
`~/.cursor/richi/session_start.py`. [Skills в Cursor](https://cursor.com/docs/skills)
и [пользовательские правила](https://cursor.com/help/customization/rules).

Откройте новый локальный чат Cursor Agent. Хук передаёт агенту точный аргумент
`--chat cursor:<id>` для каждой команды Richi, включая первый вызов `chat current`.
Выберите workspace один раз для каждого чата. Когда Cursor передаёт тот же ID,
Richi использует сохранённую привязку.
Если агент ещё не получил ID от хука, он ждёт его перед обращением к Richi. В этом
случае проверьте канал вывода Hooks в Cursor и после исправления откройте новый
чат. [Хуки Cursor](https://cursor.com/docs/hooks#sessionstart).

### Claude Code

```sh
richi setup --agent claude --dry-run
richi setup --agent claude --yes
richi setup --agent claude --status
```

Claude Code получает skill в `~/.claude/skills/richi`,
управляемый блок в `~/.claude/CLAUDE.md` и SessionStart hook в `settings.json`.
Поддерживается отдельный профиль через `CLAUDE_CONFIG_DIR`.
Существующие настройки и hooks сохраняются; ранее скопированный skill требует
`--replace-skill`, который сохраняет его резервную копию.

Откройте новую локальную сессию Claude Code. Hook передаёт настоящий ID сессии
как `RICHI_CHAT_ID=claude:<session_id>`; при продолжении используется прежний ID,
новая сессия получает отдельную привязку workspace. Если окружение недоступно,
hook сообщает агенту явный `--chat`. Отключённые политикой hooks установщик не
включает; при их отсутствии нельзя обещать автоматическую идентификацию чата.
[Каталог профиля Claude](https://code.claude.com/docs/en/claude-directory)
и [SessionStart hooks](https://code.claude.com/docs/en/hooks#sessionstart).

### Совместимость пакетов

Обновления и откаты переводят управляемые skills и скрипты сессий на выбранный
пакет одной транзакцией. До активации Richi проверяет, что для каждого
подключённого агента в релизе есть совместимый адаптер. Это касается и отката
на пакет, выпущенный до появления адаптеров Cursor или Antigravity. Изменения launcher требуют
установки нового пакета даже в режиме dev.

## Добавление другого агента в Richi

Меню ищет клиентов, которые поддерживает установленный пакет Richi. Поддержка
нового клиента требует обновления пакета; поиск не загружает сторонний код.

Зарегистрируйте встроенный адаптер в `launcher/richi_launcher/agent_adapters.py`.
Этот каталог задаёт варианты setup, установщика и пункты меню. Особенности агента
поместите в его модуль по примеру `codex_setup.py` или `claude_setup.py`:

- `LABEL` и `INSTRUCTION_LIMIT` задают название клиента и бюджет инструкций
  (`None`, если меньший лимит неизвестен).
- `detected()` проверяет CLI/профиль клиента без записи.
- `paths(current=None)` возвращает профиль, действующий файл инструкций и путь
  skill. Здесь проверяются переопределения и профиль существующей настройки.
- Если адаптеру нужен отдельный файл инструкций под управлением Richi, он может
  реализовать `instruction_file(block)`, который возвращает байты всего файла.
  Так Cursor и Antigravity получают frontmatter для своих пользовательских правил.
  Richi проверяет весь файл на локальные правки.
- `setup_operations(ctx, profile, current, replace_skill)` и
  `activation_operations(ctx, record, site)` возвращают `(extra_metadata, operations)`.
  Формируйте операции через `setup_files`, без прямой записи. При активации,
  включая откат, читайте ресурсы выбранного пакета и используйте сохранённые пути,
  а не переменные профиля из текущей оболочки.

Общий код отвечает за блокировки, ссылки skill, блоки инструкций/PATH, резервные
копии, manifest и восстановление. Режим dev тоже общий: `config set dev`
и активация переводят путь skill из `paths()` для каждого настроенного адаптера,
поэтому адаптеру не нужен отдельный код для dev; его собственные файлы
по-прежнему следуют установленному релизу. Метаданные адаптера не должны перекрывать общие
поля. Версия в каталоге описывает контракт сохраняемых данных и ресурсов адаптера,
а не релиз Richi. Совместимые релизы сохраняют её; несовместимая версия блокирует
активацию до появления явной миграции. Проверка релиза читает литералы без запуска
кода кандидата. Сохраняйте присваивания `AGENTS`, `DEV_SKILL_PROTOCOL` и
`HOOK` в адаптерах сессий литералами.

Каждый адаптер должен обеспечить стабильный ID чата и сохранить явный выбор
workspace пользователем. Проверяйте его профили и настройки в синтетическом home;
`tests/test_agent_adapters.py` проверяет общий механизм на третьем тестовом агенте.
