<a id="one-command-installation"></a>
# Установка одной командой

[English](SETUP.md) | Русский

Для **macOS/Linux с Python 3.9+, curl, sqlite3, venv и ensurepip**:

```sh
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/Hidanio/Richi/releases/latest/download/install.sh | sh -s -- --yes
```

Этот URL станет доступен после публикации стабильного релиза с установщиком;
само объединение кода релиз не публикует. В Debian/Ubuntu Python может также
потребоваться пакет `python3-venv`. Установщик сообщает об отсутствующих
компонентах и никогда не вызывает sudo и не устанавливает системный Python.
Для истории репозиториев нужен Git.

Команда устанавливает фиксированный релиз в `~/.local/share/richi/venv`, добавляет
`~/.local/bin/richi`, устанавливает Project Memory в `~/.agents/skills/` и добавляет
управляемый блок в действующие глобальные инструкции Codex. Существующие байты
инструкций, права доступа, данные и настройки workspace сохраняются. Без `--yes`
установщик показывает план и запрашивает подтверждение в терминале.

Откройте **новый чат Codex**, чтобы он обнаружил skill и инструкции. Для изменений
PATH откройте новый терминал либо сразу используйте `~/.local/bin/richi`.
Первый чат спрашивает, какой workspace использовать, и сохраняет привязку.
Пустой workspace инициализируется только после выбора. Установка никогда не
читает, не создаёт, не мигрирует и не объединяет базы знаний и не импортирует
старые чаты.

<a id="scope-and-existing-settings"></a>
## Область действия и существующие настройки

Настройка действует на локальные чаты Codex этого пользователя ОС и профиля Codex,
включая чаты без проекта. Используется `${CODEX_HOME:-$HOME/.codex}/AGENTS.md`,
если приоритет не имеет непустой `AGENTS.override.md`. Другие профили, удалённые
хосты, облачные агенты и другие агентные продукты требуют отдельной настройки.
Открытые чаты могут сохранять прежние инструкции.

Блок инструкций разрешает использовать память в рамках задачи и сохранять
полезные результаты содержательной работы. Явные запросы только на чтение и
изоляция workspace продолжают действовать. Инструкции проекта или пользователя
могут сужать поведение. Setup никогда не редактирует `config.toml`, не ослабляет
настройки согласований и не обходит отключённые skills. Успех подтверждает
установленные файлы, а не выполнение агентом каждой инструкции. Setup отклоняет
инструкции, превышающие стандартный бюджет обнаружения Codex в 32 КиБ;
меньшие пользовательские бюджеты и отключённые skills нужно согласовать в
настройках Codex. См. официальные руководства по
[skills](https://learn.chatgpt.com/docs/build-skills) и
[обнаружению инструкций](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Настройка PATH поддерживает zsh (`$ZDOTDIR/.zshrc` или `~/.zshrc`), bash
(`~/.bashrc` и первый существующий профиль входа; по умолчанию `~/.bash_profile`
на macOS или `~/.profile` на Linux), а также sh/dash (`~/.profile`).
Существующие байты сохраняются. Для другой оболочки или уже настроенного PATH
используйте `--no-path` и добавьте `~/.local/bin` самостоятельно. Desktop-агенты
могут использовать стабильную абсолютную команду из блока инструкций.

<a id="inspect-repeat-and-adopt-existing-skills"></a>
## Проверка, повторный запуск и принятие существующих skills

Чтобы изучить скрипт перед выполнением:

```sh
curl -fL --proto '=https' --proto-redir '=https' https://github.com/Hidanio/Richi/releases/latest/download/install.sh -o richi-install.sh
less richi-install.sh
sh richi-install.sh --dry-run
sh richi-install.sh --yes
```

Начальный скрипт скачивает самостоятельный установщик по HTTPS и проверяет его
SHA256 перед выполнением. Установщик проверяет контрольную сумму, размер,
идентичность и совместимость официального wheel. Контрольные суммы обнаруживают
повреждение; подлинность опирается на официальный GitHub-репозиторий и HTTPS.
Пакет с именем Richi из PyPI не загружается. Первая онлайн-установка обновляет pip
в выделенном окружении.

Повторный запуск использует принадлежащее установщику окружение, проверяет наличие
более нового стабильного релиза и согласует настройку без дублирования блоков
инструкций. Незавершённые первоначальные окружения сохраняются в резервные копии
`.interrupted-*` перед новой попыткой создания. `--dry-run` установщика показывает
только пути и необходимые компоненты; установленная команда выполняет полную
проверку конфликтов интеграции:

```sh
richi setup --dry-run
richi setup --yes
richi setup --status
```

Существующие пользовательские skills требуют явного принятия под управление:

```sh
sh richi-install.sh --yes --replace-skill
# Or, with a supported existing installation:
richi setup --yes --replace-skill
```

Существующие каталоги и ссылки перемещаются в `~/.agents/richi-skill-backups/`,
за пределы обнаружения skills. Цели символических ссылок не меняются.
Прежние копии `${CODEX_HOME}/skills/project-memory` сохраняются в
`${CODEX_HOME}/richi-skill-backups/`, чтобы избежать дублирования skills.
Посторонние файлы команд, инструкции или родительские каталоги в виде symlink,
а также изменённые управляемые блоки приводят к понятной ошибке без перезаписи.
Правки вне управляемых блоков сохраняются.

Окружение без маркера владения установщика никогда не перезаписывается.
Используйте его `richi setup`, если он поддерживается. Если постоянный bootstrap
создан до появления setup, нужен новый пустой `--prefix`: сохраните старое
окружение и согласуйте его ссылку команды перед подключением замены. Данные
workspace независимы от окружений. Никогда не запускайте `pip install -U`
в управляемой установке с подготовленными релизами.

<a id="updates-rollback-and-development"></a>
## Обновления, откат и разработка

```sh
richi update check
richi update apply
richi update rollback
```

Полный skill и справочники включаются в wheel из `skills/project-memory/`.
Обновление и откат переводят его управляемую ссылку на соответствующий пакет.
Восстанавливаемый файловый журнал согласует ссылку skill, метаданные владения
и указатель runtime. Прерванная активация завершается или отменяется при
следующем вызове CLI. Изменённые файлы skill или заменённые ссылки блокируют
активацию и сохраняются. Релизы без протокола setup не могут заменить управляемую
интеграцию. После обновления откройте новый чат: работающие агенты могут сохранять
уже загруженное содержимое skill.

Автоустановка остаётся выключенной до явного включения через
`richi update auto enable --interval 6h --install`; см. [UPDATES.md](UPDATES.ru.md).
Dev-настройки workspace сохраняются. Режим dev переключает runtime **и управляемые
ссылки skill**: `richi config set dev true` направляет каждый управляемый skill на
`<development.source>/skills/project-memory`, а `richi config set dev false`
возвращает его на установленный релиз; каждое переключение выполняется одной
восстанавливаемой транзакцией и отражается в `agent_skills`. Это относится
к каждому подключённому агенту. Блоки инструкций, файлы адаптеров, такие как
hooks, блоки PATH и запускатель остаются на установленном релизе.
Ссылки общие для пользователя и следуют последней команде `config set dev`
в любом workspace. Обновления и откаты сохраняют ссылки на checkout; перед откатом
на 1.1.0 или более старый релиз выполните `richi config set dev false`.
Подробности: [что переключает dev](INSTALLATION.ru.md#что-переключает-dev).

`richi setup --status` показывает `skill_mode` (`release` или `dev`) и ожидаемую
`skill_link`. Dev-ссылка, у checkout которой пропал skill, получает статус
`repair_required` с `dev_skill_error`; `richi setup --yes` тогда возвращает skill
релиза. Агент, подключённый при включённом dev, следует checkout. Существующая
ссылка, уже указывающая точно на управляемую цель, принимается без
`--replace-skill`; для других существующих skills он по-прежнему нужен. Setup
никогда не редактирует исходный checkout.

<a id="offline-installation"></a>
## Офлайн-установка

Скачайте `richi-installer.pyz`, его контрольную сумму, `richi-release.json` и wheel
из одного доверенного релиза. Проверьте контрольную сумму архива, затем выполните:

```sh
python3 -I richi-installer.pyz --yes --wheel richi-X.Y.Z-py3-none-any.whl --manifest richi-release.json
```

Офлайн-режим использует ensurepip без онлайн-обновления pip. Повторная установка
того же первоначального wheel идемпотентна; для другого wheel нужен новый prefix
или проверенный путь `richi update apply --version X.Y.Z`. Параметр `--version`
онлайн-установщика закрепляет версию wheel, а не загрузку bootstrap. Перед
публикацией release workflow проверяет точные wheel и установщик на Python
3.9/3.12 и macOS/Linux; см. [RELEASING.md](RELEASING.ru.md).

<a id="backups-recovery-and-removal"></a>
## Резервные копии, восстановление и удаление

`richi setup --status` работает только на чтение и показывает управляемые пути
и ожидающее восстановление. Вывод setup содержит приватный каталог
`setup-backups`. Его JSON-файлы сохраняют исходные байты (base64), права доступа,
ссылки и пути резервных копий принятого skill. Они могут содержать приватные
инструкции: не публикуйте их. Сохраняйте ожидающий обработки `setup-pending.json`
и поколения установки для восстановления. Если после сбоя файлы менялись,
сохраните обе версии и согласуйте указанный путь перед повторной попыткой;
автоматическое восстановление откажется перезаписывать такие изменения.

Для ручного отключения сначала выключите автоматические обновления. Удалите
только блок с маркерами `richi:project-memory` из указанного файла глобальных
инструкций и блоки `richi:path` из указанных профилей. Проверьте цели перед
удалением управляемых ссылок skill и команды; при необходимости восстановите
указанную резервную копию skill. Затем удалите выделенное окружение и метаданные
его установки, если они больше не используются. Сохраните данные workspace.
В этом релизе нет автоматического деинсталлятора; для удаления интеграции никогда
не требуется удалять весь AGENTS.md.

## Подключение Claude Code и новых агентов

`richi agents` открывает меню подключения Codex и Claude Code. Пункт повторного
поиска пригодится, если агент установлен после Richi. Обнаружение по CLI или
каталогу профиля — подсказка, а не проверка работоспособности самого клиента.
`richi agents --status` показывает состояние без записи.

```sh
richi setup --agent claude --dry-run
richi setup --agent claude --yes
richi setup --agent claude --status
```

Для первоначальной установки передайте `--agent claude` установщику.
По умолчанию остаётся Codex. Чтобы подключить оба клиента, выполните setup
отдельно для каждого. Claude Code получает skill в `~/.claude/skills/project-memory`,
управляемый блок в `~/.claude/CLAUDE.md` и SessionStart hook в `settings.json`.
Поддерживается отдельный профиль через `CLAUDE_CONFIG_DIR`.
Существующие настройки и hooks сохраняются; ранее скопированный skill требует
`--replace-skill`, который сохраняет его резервную копию.

Откройте новую локальную сессию Claude Code. Hook передаёт настоящий ID сессии
как `RICHI_CHAT_ID=claude:<session_id>`; при продолжении используется прежний ID,
новая сессия получает отдельную привязку workspace. Если окружение недоступно,
hook сообщает агенту явный `--chat`. Отключённые политикой hooks установщик не
включает; при их отсутствии нельзя обещать автоматическую идентификацию чата.
Это интеграция Claude Code, не обычного чата Claude и не MCP-сервер.

Обновления и откаты переводят управляемые skill и скрипт сессии Claude на выбранный
пакет одной транзакцией. Пакет, который не умеет обслуживать хотя бы одного
подключённого агента, не активируется. Изменения launcher требуют установки
нового пакета: режим dev не обновляет команду setup.

Контракты Claude: [каталог профиля](https://code.claude.com/docs/en/claude-directory)
и [SessionStart hooks](https://code.claude.com/docs/en/hooks#sessionstart).

## Добавление другого агента в Richi

Меню ищет клиентов, которые поддерживает установленный пакет Richi. Поддержка
нового клиента требует обновления пакета; поиск не загружает сторонний код.

Зарегистрируйте встроенный адаптер в `launcher/richi_launcher/agent_adapters.py`.
Этот каталог задаёт варианты setup, установщика и пункты меню. Особенности агента
поместите в его модуль по примеру `codex_setup.py` или `claude_setup.py`:

- `LABEL` и `INSTRUCTION_LIMIT` задают название клиента и бюджет инструкций
  (`None`, если меньший лимит неизвестен).
- `detected()` проверяет CLI/профиль клиента без записи.
- `paths(current=None)` возвращает профиль, действующий файл инструкций и путь
  skill. Здесь проверяются переопределения и профиль существующей настройки.
- `setup_operations(ctx, profile, current, replace_skill)` и
  `activation_operations(ctx, record, site)` возвращают `(extra_metadata, operations)`.
  Формируйте операции через `setup_files`, без прямой записи. При активации,
  включая откат, читайте ресурсы выбранного пакета и используйте сохранённые пути,
  а не переменные профиля из текущей оболочки.

Общий код отвечает за блокировки, ссылки skill, блоки инструкций/PATH, резервные
копии, manifest и восстановление. Режим dev тоже общий: `config set dev`
и активация переводят путь skill из `paths()` для каждого настроенного адаптера,
поэтому адаптеру не нужен отдельный код для dev; его собственные файлы
по-прежнему следуют установленному релизу. Метаданные адаптера не должны перекрывать общие
поля. Версия в каталоге описывает контракт сохраняемых данных и ресурсов адаптера,
а не релиз Richi. Совместимые релизы сохраняют её; несовместимая версия блокирует
активацию до появления явной миграции. Проверка релиза читает литералы без запуска
кода кандидата. Сохраняйте присваивания `AGENTS`, `DEV_SKILL_PROTOCOL` и Claude
`HOOK` литералами.

Каждый адаптер должен обеспечить стабильный ID чата и сохранить явный выбор
workspace пользователем. Проверяйте его профили и настройки в синтетическом home;
`tests/test_agent_adapters.py` проверяет общий механизм на третьем тестовом агенте.
