# Составные фильтры и индексированный поиск

[English](FILTERS.md) | Русский

Используй `--where` в `discover`, `recall` или `search`, когда вопрос требует строгой области поиска.
Запрос по-прежнему задаёт лексическую опору. Для полных операций над метаданными без
лексического предварительного отбора см. [QUERY_TOOLS.ru.md](QUERY_TOOLS.ru.md). Все существующие правила состояния,
происхождения, числа результатов и бюджета символов сохраняются.

```sh
richi --compact-json recall 'connection pooling' \
  --where "project = 'example' AND kind IN ('decision', 'experiment') AND NOT work_state = 'planned'"
richi --compact-json recall 'cache' \
  --where "(tags HAS 'performance' OR aliases HAS 'local cache') AND verified_at IS NOT NULL"
richi search 'cache' --where "family = 'entry' AND title LIKE 'Cache%'"
```

`--project` в recall остаётся повышающим коэффициентом ранжирования. `project = 'example'` внутри
`--where` требует обязательной принадлежности. Фильтр применяется **до** предварительного отбора FTS,
до загрузки полезной нагрузки и к добавлениям из графа; посторонние узлы графа не могут
обойти его. Результат с ограниченной областью описывает только эту область, включая сообщаемую
неоднозначность концептов. `search` возвращает только entries; recall также ищет entities.

Поддерживаемые операции:

| Операция | Значение |
|---|---|
| `AND`, `OR`, `NOT`, скобки | Приоритет: NOT, затем AND, затем OR |
| `=`, `!=`, `<`, `<=`, `>`, `>=` | Скалярные сравнения |
| `IN ('a', 'b')`, `NOT IN (…)` | Принадлежность списку литералов |
| `IS NULL`, `IS NOT NULL` | Явные проверки отсутствующего значения |
| `LIKE`, `NOT LIKE` | `%` соответствует последовательности символов; `_` — одному символу; обратная косая черта экранирует их |
| `tags HAS 'x'`, `aliases HAS 'x'` | Точная принадлежность массиву; также поддерживается `NOT HAS` |

Поля: `family` (`entry` или `entity`), `id`, `kind`, `knowledge_state`,
`work_state`, `jira_key`, `title`, `project`, `tags`, `aliases`, `created_at`,
`updated_at`, `verified_at`. Значения — строки в одинарных кавычках; вложенную
кавычку удваивай (`'team''s decision'`). Произвольный SQL, подзапросы, функции и комментарии
отклоняются. Парсер ограничивает длину выражения, вложенность и размеры списков.
`id` — собственный идентификатор записи; при необходимости сочетай его с `family`.

Скалярное равенство и HAS учитывают регистр. LIKE следует стандартным правилам SQLite:
регистр букв ASCII не учитывается; регистр остальных букв учитывается. Эти
явные предикаты отличаются от лексического поиска recall с нормализацией Unicode.
Равенство, порядок и IN для дат сравнивают даты и временные метки ISO через SQLite
`julianday`, включая смещения часовых поясов; дата без времени означает полночь UTC.
Резервный путь только для чтения нормализует ранее допустимые формы временных меток, которые SQLite
не может разобрать непосредственно. Некорректные сохранённые даты вызывают ошибку, а не незаметно
исчезают из результатов. Предикаты дат могут требовать сканирования; эта версия индексирует ключи
маршрутизации и поля state/kind/work-state, а не каждую поддерживаемую операцию фильтра.
Точность соответствует функциям дат SQLite (миллисекунды), поэтому они не подходят
для различения ревизий в пределах одной миллисекунды. LIKE для поля даты по-прежнему
сопоставляет сохранённый текст. При обновлении записи используй точное значение `updated_at`
с существующим API записи с оптимистической проверкой конкурентных изменений.
У entities поля `work_state` и `jira_key` равны NULL. Действует трёхзначная логика SQL:
`NOT work_state = 'planned'` не выбирает NULL; используй
`work_state IS NULL OR work_state != 'planned'`, если отсутствие состояния допустимо.

Проекты entry определяются явной принадлежностью. Область концепта требует
исходящего подтверждённого ребра `used_in` к проекту с источниками. Для других видов entity
нужно подтверждённое ребро к проекту с источниками в любом направлении. Несколько проектов
образуют множество: положительные предикаты project означают любую совпавшую принадлежность; отрицательные —
отсутствие совпадений, включая записи без области. `project IS NULL` выбирает только
записи без области. Гипотезы и superseded-записи по-прежнему исключены из recall, если не переданы
существующие флаги включения, даже когда фильтр явно называет это состояние.

## Включи производный индекс явно

```sh
richi search-index status
richi search-index build
```

Эти команды используют выбранный workspace чата. Для задачи по репозиторию сохраняй
обычную проверку `--project-path PATH`. Build атомарно создаёт или перестраивает производные ключи поиска
и индексы фильтров. Знания, история, источники, версия схемы и выбор runtime
не меняются. Существующие хранилища никогда не обновляются командой чтения
или выбором нового runtime. Фильтры работают и без этого индекса.

Индекс направляет поиск по нормализованным ID, ключам Jira и алиасам и сужает лексических
кандидатов entities. Полная оценка, проверки состояния и правила графа остаются определяющими;
точное совпадение не отбрасывает других кандидатов. Новые записи обновляют свои ключи
внутри транзакции записи. SQL-триггеры помечают записи от старых runtime как dirty,
поэтому читатели включают их через резервный путь до обновления или перестроения.
При отсутствии индексов, слишком больших входных данных и неподдерживаемых версиях индекса используется безопасное
сканирование. Индекс не хранит источники, снимки истории или сохранённые байты Git.

Используй `--explain` для просмотра фактически посещённых и оценённых строк; `--expect REF` объясняет
отсутствие известной записи, включая `filtered_where`. Диагностика использует общий бюджет
вывода; измеряй её отдельно от обычного поиска. Построение индекса требует диска
и операций записи ради сокращения чтения; измеряй результат на синтетическом или
разрешённом скопированном хранилище, прежде чем заявлять об ускорении. Число токенов
ответа без фильтров должно оставаться прежним. Экономия токенов достигается исключением нерелевантных
результатов и повторных уточняющих вызовов, а не удалением свидетельств из найденных
записей. Перед выводами по-прежнему нужно прочитать полные релевантные записи.
