# Прочитать связи вокруг известной записи

[English](NEIGHBORS.md) | Русский

```sh
richi --compact-json --project-path /work/example graph neighbors \
  entry:task:EXAMPLE-42 --depth 1 --limit 30 --view compact --max-chars 12000
```

Refs имеют вид `project:<project-id>`, `entry:<full-entry-id>` или
`entity:<full-entity-id>`; сохраняй всё после первого двоеточия.
`neighbors` проходит по входящим и исходящим связям. Глубина — 1–3, по умолчанию 1;
лимит — 1–200 узлов, включая корневой, по умолчанию 200; циклы не дублируются.
Начни с области, нужной для вопроса. Не экспортируй весь граф,
если достаточно локального окружения.

Для ограниченного чтения используй `--view compact`. Бюджет сериализованного JSON по умолчанию —
16000 символов, допустимо 2000–100000, включая форматирование и завершающий перевод строки;
`--compact-json` оставляет больше места данным. Сам по себе `--limit` ограничивает число узлов,
а не размер текста. По умолчанию `--view full` сохраняет полные записи и не принимает
`--max-chars`; вывод `graph export` и карты не меняется.
Бюджет ограничивает текст ответа, а не объём работы базы или временную память.

По умолчанию показываются только confirmed-узлы и рёбра. При необходимости независимо добавляй
`--include-hypotheses` и/или `--include-superseded`. Отфильтрованные endpoints
скрывают соответствующие рёбра; отфильтрованный корень даёт пустой граф, а не доказательство отсутствия связей.
Проверяй `truncated`, `limits`, `budget`, выдержки, пропуски источников и `scope`.
`limits` описывает лимиты отбора и отсоединённые записи, пропущенные после лимита рёбер;
`budget` считает пропуски из этого связного набора. Счётчики не претендуют
на покрытие невидимых узлов и рёбер за пределами лимитов отбора. Compact сохраняет
корень и путь к каждому показанному узлу, но может убрать другие рёбра или целые ветви.
Если payload корня не помещается, его точный ref/state остаётся с `payload_omitted`;
для полных данных повтори `graph neighbors` для `scope.root` с `--view full`.
Выбранная глубина задаёт область,
а не признак усечения; отсутствие за её пределами не доказывает отсутствие отношения.

Смысл определяется направлением, kind и источниками. Общее членство или путь в графе
не доказывает причинность. `belongs_to_project` выводится из `entry.project_ids`;
его наличие не означает техническое влияние. В compact его `sources_ref`
указывает на исходную entry вместо повторения её свидетельств;
`provenance` сохраняет производное происхождение. Другие рёбра показывают целые объекты источников
со счётчиками пропусков. До обновления или вывода, зависящего от условий, читай
полные payload соответствующих узлов/рёбер по `read_more`. Для явного ребра
передай native ID в `edge get`, удалив только добавленный экспортом префикс `edge:`.
Другие происхождения (`membership:`, `relation:`) — производные, это не ID для `edge get`.
Для отношения проектов выполни `read_more.args`: там используется
`context --project=ID --limit 1 --include-superseded`, затем выбери точное
отношение из `read_more.select`. Так сохраняются исторические и hypothesis-
строки и обходятся лимиты узлов графа. Этот limit ограничивает только entries; список
отношений читается полностью и может быть большим.

Схема, запись рёбер, полный экспорт графа, миграции и отображение карты:
[GRAPH.ru.md](GRAPH.ru.md). Изменения при очистке: [MAINTENANCE.ru.md](MAINTENANCE.ru.md).
Не создавай обратные рёбра только ради навигации и не дублируй членство вручную.
