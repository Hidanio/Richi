# Точные операции над метаданными

[English](QUERY_TOOLS.md) | Русский

Используй привязанный workspace и обычную проверку `--project-path PATH`. Эти операции только для чтения
выполняются внутри SQLite и не требуют построения необязательного индекса.
Применяй их к вопросам о сохранённых метаданных, а не для выводов о содержимом записей.

```sh
richi --compact-json query count --project example --where "kind = 'decision'"
richi --compact-json query exists --project example --where "jira_key = 'DEMO-42'"
richi --compact-json query facets --project example --by kind --by work_state
richi --compact-json query select --project example \
  --fields ref,title,work_state,verified_at --limit 50
```

`count` и `exists` охватывают **все** подходящие текущие записи, без лексического
или FTS-отбора. `exact: true` относится к сохранённой области, а не к внешней действительности.
Они не читают summaries, источники, историю ревизий или артефакты Git. `exists`
останавливается после первого совпадения. Используй его для проверки принадлежности по метаданным; неудачный
лексический поиск по-прежнему не доказывает, что работа никогда не проводилась.

`--project` является **строгим** для каждой операции `query`. Это отличается от
повышающего коэффициента ранжирования recall/discover. `--where` использует ту же ограниченную составную грамматику
и семантику происхождения project, дат и NULL из [FILTERS.ru.md](FILTERS.ru.md); он сочетается
с селекторами проекта и состояния. Семейство по умолчанию — `entry`; используй
`--family entity` или `--family all`. У entities поля work_state и jira_key равны NULL.
Состояние знаний по умолчанию — confirmed; включай hypotheses/superseded осознанно
отдельными флагами. Фильтр не может обойти эти ограничения состояния. Хранилища schema-1
поддерживают entries; all использует доступные семейства, entity требует schema 2.
Каждый ответ сообщает фактическую область поиска.

`facets --by FIELD` возвращает параллельные `columns` и `rows`, сгруппированные по одному — трём
различным полям: family, kind, knowledge_state, work_state, jira_key. Повторяй
`--by` для составных групп. Счётчики точны для каждой возвращённой группы. NULL
образует отдельную группу, а не пустую строку. Группы сортируются по убыванию счётчика, затем
по бинарному порядку полей; `--limit` (1–200, по умолчанию 20) и бюджет символов ограничивают
возвращённые группы. `has_more: true` означает пропущенные группы; их счётчики не равны
нулю. Если нужны все группы, сузь область или увеличь лимиты. Группа,
которая не помещается в бюджет JSON, пропускается целиком, даже если она первая;
`has_more` остаётся true. Ключи выше отдельного предела загрузки (четыре значения
max-chars в байтах UTF-8) вызывают явную ошибку до загрузки в Python. Сузь
предикат или увеличь бюджет. У этой операции нет курсора пагинации.

`select` проецирует только запрошенные скалярные поля: id, kind, title, knowledge_state,
work_state, jira_key, created_at, updated_at, verified_at. `ref` всегда идёт первым;
поля по умолчанию — ref,kind,title,knowledge_state,work_state,verified_at. Компактная
таблица содержит `columns` и соответствующие `rows`; поля никогда не обрезаются незаметно.
Полные записи, массивы и произвольные SQL-выражения не входят в проекции.
Для полных свидетельств, включая источники и оговорки, используй `fetch --ref REF`.

Страницы сортируются по полному квалифицированному ref в бинарном порядке. `--limit` — 1–200 (по умолчанию 20).
Пока `has_more` равен true, повторяй **ту же область и поля** с
`--after next_after`. Элемент `oversized` — подходящая запись, запрошенные
метаданные которой не поместились; он содержит точный указатель fetch и считается обработанным
при продолжении. Это не отсутствующая запись. При перечислении области собирай строки
и результаты oversized. Значение `returned` страницы не задаёт полного числа строк.
Страница использует один снимок чтения; каждое продолжение открывает новый. Конкурентные
записи могут изменить перечисление. Перед обновлением перечитай запись и используй точную
текущую версию для оптимистической проверки конкурентных изменений.

Каждая операция принимает `--max-chars` 2000–100000 (по умолчанию 8000). Бюджет охватывает
фактический JSON вместе с завершающим переводом строки; `--compact-json` вмещает больше метаданных.
Сама работа SQL может сканировать подходящие записи: группировка, произвольный LIKE, принадлежность
массиву и предикаты дат не всегда индексированы. Проекция не загружает содержимое;
пагинация по ключам использует диапазоны собственных ID. SQLite может выбрать индекс
фильтра с сортировкой вместо индекса первичного ключа. Чтение не выполняет retention,
автоматическое удаление, миграцию схемы или построение индекса в рабочем хранилище.
