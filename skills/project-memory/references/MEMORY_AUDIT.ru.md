# Аудит выбранной памяти без изменений

[English](MEMORY_AUDIT.md) | Русский

Используй по явному запросу на очистку, объединение или аудит. Оставайся в пределах
запрошенного проекта, темы и записей; обычная проектная работа не требует
проверки всего хранилища. Запрос только на аудит разрешает чтение и рекомендации,
а не запись. Запрос на саму очистку разрешает обоснованные обратимые правки в его границах;
перед применением используй [MAINTENANCE.ru.md](MAINTENANCE.ru.md). Для аудита backup не нужен.

<a id="select-and-read-candidates"></a>

## Выбери и прочитай кандидатов

Если пользователь назвал записи, сразу читай их полные payload через `entry/entity/edge get`.
Добавляй историю, только если важны прежние значения или хронология. Если кандидаты
неизвестны, начни с:

```sh
richi --compact-json --project-path /work/example punisher \
  --project service-example --limit 20 --max-chars 16000
```

Не указывай проект/путь только при намеренном аудите всего workspace. Punisher
возвращает состояние SQLite и кандидатов на рассмотрение, ничего не изменяя. Его
область проекта строгая: членство entries и прямые confirmed-связи
`used_in` с источником от entity к проекту. `recall --project` повышает релевантность;
`graph export --project` возвращает связную компоненту, которая может пересекать проекты.
Ни один из них не расширяет разрешение на редактирование других знаний.

Находки вроде одинакового текста, общих aliases, отсутствующих дат/источников, старой
проверки или длинных summary — повод изучить запись, не доказанные дефекты.
`--summary-warn-chars` по умолчанию равен 6000; сама длина не доказывает смешение
истории, низкое качество или необходимость разделения. Точные контракты находок и лимиты
сканирования описаны в [DIAGNOSTICS.ru.md](DIAGNOSTICS.ru.md#кандидаты-для-ручного-обслуживания).

Проверяй `coverage.complete`, `truncated`, `budget`, пропущенные находки и лимиты графа,
прежде чем заявлять полноту. Работай небольшими группами; читай полные payload кандидатов
и соответствующие инцидентные связи через [NEIGHBORS.ru.md](NEIGHBORS.ru.md). Ограниченный
отчёт не доказывает отсутствие других кандидатов. Для полного обзора сузь
или раздели область либо перечисли метаданные из разрешённого согласованного
read-only снимка; не выгружай всю базу в контекст модели.

Проверяй внешние источники, только когда они нужны для вывода. Отсутствующие файлы —
пробелы в источниках, а не автоматическое опровержение исторических наблюдений. Предпочитай
уже известную стабильную замену; не утверждай, что непрочитанные свидетельства проверены.

<a id="decide-whether-content-should-be-combined"></a>

## Реши, нужно ли объединять содержимое

| Находка | Решение |
|---|---|
| Одинаковый смысл, область/версия и дублирующее или дополняющее содержимое | Предложи одну каноническую запись, сохраняя каждое полезное утверждение и его provenance |
| Исследование и выведенное из него определение | Сохрани обе роли; свяжи при наличии свидетельств |
| Разные контракты, версии, значения или условия экспериментов | Оставь отдельно; добавляй только подтверждённые свидетельствами отношения |
| Противоречащие результаты | Сохрани оба с условиями и источниками; не усредняй |
| Задача с полезными самостоятельными подробностями | Сохрани стабильный ID задачи; рассматривай разделение, только если можно сохранить поиск и условия |
| Повторяющийся текст | Удали только повторы, сохранив утверждения, числа, условия и ограничения |
| Неясная ценность или неподтверждённое объяснение | Оставь без изменений и явно укажи неопределённость |

Общий tag, Jira, alias, источник или путь графа не доказывает дублирование
или причинность. Предпочитай стабильные ID; короткая Jira-задача не должна поглощаться
исследованием или понятием только из-за длины. Варианты терминов с областью применения:
[ENCYCLOPEDIA.ru.md](ENCYCLOPEDIA.ru.md).

Сохраняй неудачные эксперименты, причины отказа от подходов, исторические
измерения и условия воспроизведения. Различай hypothesis и confirmed;
редактирование не обновляет проверку и не повышает достоверность. Implemented,
merged и released остаются разными состояниями. Более поздний результат не заменяет
автоматически прежний в других условиях. Supersession оправдана,
только если реальная замена сохраняет полезное содержимое и остаётся доступна поиску.

Сообщи проверенную область, свидетельства, границы покрытия, рекомендуемые изменения и
случаи, оставленные раздельными или нерешёнными. Если правка не обоснована, скажи это. Число карточек,
размер SQLite и сокращение текста сами по себе не доказывают рост полезности.
