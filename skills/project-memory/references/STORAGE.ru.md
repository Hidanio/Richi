# Размер хранилища и явное обслуживание индексов

[English](STORAGE.md) | Русский

Используй для запрошенной диагностики или обслуживания хранилища, не перед обычным поиском.
Workspace выбирается по [SKILL.ru.md](../SKILL.ru.md). Эти операции охватывают
базу выбранного workspace, даже если путь проекта проверяет членство.

```sh
richi --compact-json storage stats --deep --files --max-chars 8000
richi --compact-json storage optimize
# Only within authorized index maintenance:
richi --compact-json storage optimize --apply
```

`stats` работает только на чтение. Обычные счётчики и размеры страниц/файлов разделены;
`--deep` добавляет логические байты текста и необязательное распределение физических страниц;
`--files` составляет ограниченную опись известных каталогов, не читая содержимое
и не переходя по ссылкам. Проверяй `coverage`, `budget.omitted_sections` и недоступные
возможности. Одно наблюдение показывает размер, а не скорость роста. Наблюдения файловой системы
и базы не образуют атомарный снимок. WAL, свободные страницы, история, backups и
eval-файлы нельзя смешивать с текущими знаниями, доступными поиску.

`optimize` по умолчанию возвращает план без записи. Явный `--apply` отклоняет
`--project-path`, создаёт проверенный SQLite backup, затем выполняет поддерживаемое
обслуживание индексов FTS/planner в атомарной транзакции. Статистика планировщика SQLite
может измениться. При ошибке изменения индексов откатываются, backup сохраняется. Операция не
удаляет знания/историю/events/файлы, не выполняет VACUUM, checkpoint, миграцию прикладной
схемы и не продвигает даты проверки. Успех не доказывает ускорение
или уменьшение диска; сравни соответствующие измерения.

Backups не включают blobs Git-свидетельств и объекты репозитория. Сохраняй их
для восстановления. Никогда вручную не удаляй WAL/SHM, не очищай неизменяемую историю или
события идемпотентности и не собирай Git blobs на удаление только по текущим записям. Исторические
ссылки и capture-before-attach могут всё ещё требовать эти объекты. Холодный архив требует
отдельно рассмотренного контракта хранения и восстановления. Для смысловой очистки используй
[MEMORY_AUDIT.ru.md](MEMORY_AUDIT.ru.md) и [MAINTENANCE.ru.md](MAINTENANCE.ru.md).
