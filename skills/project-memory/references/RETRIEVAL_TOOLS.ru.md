# Найди маршруты, затем получи полные записи

[English](RETRIEVAL_TOOLS.md) | Русский

Используй этот двухэтапный путь, когда релевантные refs ещё предстоит выбрать. Для небольшого
набора entries, уже заданного лексическим запросом и строгими предикатами, `search QUERY
--where EXPR` может вернуть полные совпадения за один вызов; см. [FILTERS.ru.md](FILTERS.ru.md).
Search остаётся ограниченным лексическим поиском: для полных счётчиков метаданных,
проверки существования и постраничных перечней используй `query`. Известный ref сразу направляется в get/fetch.

```sh
richi --compact-json --project-path /work/example discover 'pool sizing' --project example
richi --compact-json --project-path /work/example fetch \
  --ref entry:experiment:pool-sizing --ref entity:concept:connection-pool --max-chars 16000
```

`discover` — компактное представление для маршрутизации: по умолчанию восемь результатов, 8000 символов;
`--limit` 1–200, `--max-chars` 2000–100000. Используются те же ранжирование, проверки ключей задач,
явное расширение на один шаг и повышение рейтинга проекта, что и в `recall`. Повышение рейтинга проекта
не является строгим фильтром. Используй `--where "project = 'example' AND kind = 'decision'"`
для обязательной области до лимитов кандидатов и расширения графа; см. [FILTERS.ru.md](FILTERS.ru.md).
Выводятся только подтверждённые знания, если отдельно не включены
`--include-hypotheses` / `--include-superseded`.
Бюджет ограничивает возвращаемый текст, а не CPU поиска или пиковую память: discovery по-прежнему
использует сканирование кандидатов и загрузку записей recall.

Карточки содержат не более 300 символов дословной выдержки и не содержат полезной нагрузки источников.
`source_count` / `sources_omitted` охватывают полную запись. Маршруты рёбер сохраняют
происхождение, направление, состояние и точный указатель свидетельства. Используй `read_more.args`
как структурированные аргументы; сохраняй всё после первого двоеточия в ссылке.
**Discovery недостаточно для выводов или обновлений**, даже если выдержка
поместилась полностью. Прочитай полные релевантные записи и проверь авторитетные источники
текущего состояния. Баллы ранжируют совпадения; это не вероятности истинности.

`ambiguity.detected` и общее число концептов сохраняются при малом бюджете.
Пропущенные альтернативы не доказывают единственность значения. Пустые результаты при
`no_match=false` означают, что подробности совпадений не поместились. `no_match=true` означает отсутствие
индексированного совпадения, а не доказательство того, что работы никогда не было. Счётчики описывают
кандидатов поиска, а не всю базу. Ограничения ранжирования и покрытия см. в [RECALL.ru.md](RECALL.ru.md),
диагностику известного пропуска — в [RECALL_DEBUG.ru.md](RECALL_DEBUG.ru.md).

`fetch` принимает до 32 уникальных refs `entry:`, `entity:`, `edge:` или `project:`.
Дубликаты удаляются с сохранением порядка первого появления. Чтение использует один согласованный
снимок и возвращает **полные текущие записи без истории**. Явные refs
могут вернуть любое состояние знаний. Запись `found` равна полной полезной нагрузке get;
записи проектов равны соответствующим элементам `project list`.

Результаты `missing`, `oversize` и `read_limit` явные и содержат
точный указатель чтения. `oversize` означает, что целая запись не помещается в этот ответ;
увеличь бюджет или используй отдельный get. Для проектов нет отдельного get;
если проект превышает максимальный бюджет, `project list` возвращает полные записи проектов
в выбранном workspace и не ограничен бюджетом. `read_limit` означает, что закодированное хранилище
слишком велико для ограниченного чтения, а не доказанный размер сериализации. Изучай такие
записи отдельно только при необходимости. Fetch по умолчанию использует 16000 символов;
те же границы 2000–100000 включают всё форматирование JSON и завершающий перевод строки,
а не токены или байты UTF-8. Компактный JSON обычно вмещает больше полных записей.

Если `remaining_count` не равен нулю, повтори **исходный список refs в том же
порядке** с `--offset next_offset`. Сохраняй этот входной список: длинные оставшиеся ID
не дублируются в ответе. Каждое продолжение видит новый снимок; перед обновлением перечитай
запись и используй оптимистическую проверку конкурентных изменений. `request_complete` означает, что все
refs начиная с этого смещения обработаны; missing/oversize не считаются успешными
чтениями. `all_requested_records_returned` равен true только если один вызов с нулевого
смещения возвращает все запрошенные записи целиком. Для записи следуй
[ENTRY_WRITE.ru.md](ENTRY_WRITE.ru.md); никогда не отправляй карточку discovery как замену записи.
